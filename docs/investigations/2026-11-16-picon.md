# Picon as a future count source

Requested for later consideration on November 16, 2026. No integration or
count requests were made. The service's documentation was read at
[picon.atverkackt.de](https://picon.atverkackt.de/).

The documented endpoint is `de.atverkackt.icarus.getProfile`, taking an actor
identifier and returning DID, handle, follower count and following count.
Picon describes folding repository snapshots from Hubble to repair its follow
graph. Those are provider claims, not coverage or freshness measurements here.
It is a possible source for Typeahead's count enrichment, leaving downstream
`getProfiles` consumers such as Coral unchanged. It does not replace other
profile fields, post counts, activity signals or moderation information.

Before adoption, establish coverage, freshness, deletion handling and a
provider-friendly quota. The site warns that zero following count can mean
not yet indexed, and follower counts fill gradually as other repositories are
read. Never overwrite known counts or ranking scores with ambiguous zeros.
Use DIDs to avoid handle-resolution requests, cache slow-moving counts, and
honor backoff. The documented endpoint has no batch API. Existing AppView
fallback and provenance need an explicit policy before changing enrichment.
